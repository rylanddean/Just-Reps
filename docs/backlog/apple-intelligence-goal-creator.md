# Apple Intelligence Goal Creator

> Tell it where you're starting. It remembers where you've been.

---

## Summary

A conversational goal-setting flow powered by Apple Intelligence (on-device Foundation Models). Instead of guessing a starting number or fiddling with a stepper, the user has a short natural-language exchange — the model asks a question or two, proposes a goal, and the user confirms. Over time, the same model resurfaces during natural checkpoints to suggest increases, framed as encouragement rather than evaluation.

This is the human-first alternative to algorithmic nudges. The user is in the conversation, not just receiving an output.

---

## How this differs from AI Adaptive Goals

| | AI Adaptive Goals | Apple Intelligence Goal Creator |
|---|---|---|
| Trigger | Automatic, weekly | User-initiated or at natural checkpoints |
| Interaction | One tap (Update / Keep) | Short conversation |
| Tone | Silent suggestion | Warm, responsive dialogue |
| Goal setting | Adjustment only | First-time setup AND ongoing increases |
| Model | On-device heuristic → Claude API V2 | Apple Intelligence Foundation Models (always on-device) |

These features complement each other. The Goal Creator sets intent. Adaptive Goals maintains it quietly in the background.

---

## Why it fits the brand

Goal-setting is the moment most fitness apps lose people. A blank number field with no context is intimidating. A single clarifying question — *"Do you do pushups now, or are you starting from zero?"* — removes the intimidation without adding friction.

The tone must feel like a knowledgeable friend, not a coach with a clipboard. No assessment. No score. Just a short conversation that ends with a number the user actually believes in.

Privacy is non-negotiable: every word of the conversation stays on-device. Apple Intelligence Foundation Models guarantee this with no configuration.

## Apple Intelligence technical approach

**Framework:** `FoundationModels` (iOS 18.1+, Apple Intelligence required)

**Key APIs:**
- `SystemLanguageModel.default` — the on-device model accessed via the Foundation Models framework
- `LanguageModelSession` — manages a multi-turn conversation with context
- `@Generable` — structures the model's response (goal number + rationale string) into a typed Swift value

**Session lifecycle:**
1. A new `LanguageModelSession` is created with a system prompt defining the assistant's role, the user's logged history (exercise names, recent rep counts, current goals), and strict output format
2. Each user message is sent via `session.respond(to:)`
3. The session holds conversation context automatically — no manual prompt concatenation
4. When the user confirms a goal, the session is discarded; only the final number is persisted

**System prompt principles:**
- Role: "You help people set achievable daily rep goals. Ask at most one clarifying question. Always propose a specific number. Never give fitness advice or suggest exercises."
- Context injection: current goals, last 7 days of rep counts per exercise, days-per-week frequency
- Output schema: `GoalSuggestion { exercise: String, reps: Int, message: String }`

**Siri / App Intents (V2):**
- `SetGoalIntent` — "Hey Siri, update my pushup goal in Just Reps"
- Siri hands off to the in-app conversation UI after confirming exercise name

## UX flow

### First-time goal setup (replaces the blank number field)

Triggered when a user enables a new exercise for the first time and has no existing goal.

```
┌────────────────────────────────────┐
│  Let's set your pushup goal.       │
│                                    │
│  How many can you do right now,    │
│  roughly?                          │
│                                    │
│  [ Type a number or a word... ]    │
└────────────────────────────────────┘
```

User types "maybe 15" → model responds:

```
┌────────────────────────────────────┐
│  Start at 20 a day — it'll feel    │
│  easy at first. That's the point.  │
│                                    │
│  [ Set goal: 20 ]  [ Change it ]   │
└────────────────────────────────────┘
```

One exchange. Done. The number is set.

---

### Ongoing increase moments

Triggered at one of three checkpoints (whichever comes first):
- User has beaten their goal 5 days in a row
- User sends a message like "I want to increase my pushups"
- Weekly suggestion card is dismissed 3 weeks running (they want more control)

The UI is a subtle sheet from the bottom — not a modal interrupt:

```
┌────────────────────────────────────┐
│  You've been hitting 35+ pushups   │
│  every day this week.              │
│                                    │
│  Ready to move to 40?              │
│                                    │
│  [ Yeah, let's do it ]  [ Not yet ]│
└────────────────────────────────────┘
```

The message is generated by the model from the injected history. "Not yet" snoozes the prompt for 2 weeks — no repeat nagging.

---

### Manual access

Settings → Goals → [Exercise] → "Chat about this goal"

Opens a persistent session where the user can ask anything goal-related: "Is 40 too ambitious?" / "I've been sick, should I lower it?" The model has full rep history and responds accordingly.

## Copy principles

- Questions only — the model never tells the user what they *should* do
- Propose, don't prescribe: "Start at 20" not "You need to do at least 20"
- Downward adjustments are valid: "Taking it down to 15 makes sense. Consistency beats volume every time."
- Maximum one follow-up question per conversation before proposing a number

---

## Failure states

| Condition | Behaviour |
|-----------|-----------|
| Apple Intelligence not available (device / region) | Feature hidden entirely; falls back to manual stepper |
| Model response malformed | Show typed fallback: "Try starting at [N]" where N = StreakEngine heuristic |
| User gives unusable input ("idk", "lots") | Model asks one clarifying question; if still unusable, suggest a safe default |
| Session error | Silent retry once; then dismiss with "You can set this manually in Settings" |

---

## Constraints

- **iOS 18.1+, Apple Intelligence required** — feature is gated and hidden on unsupported devices
- **On-device only** — zero network calls, zero data retention after session ends
- **No conversation history persisted** — only the final accepted goal number is saved
- **Context window:** inject at most 30 days of rep history to stay well within token limits
- **No fitness advice** — model is constrained by system prompt to goal numbers only; medical/injury questions get "I can only help with rep counts — talk to someone who knows your body"

- [ ] `LanguageModelSession` used with structured `@Generable` output (goal number + message string)
- [ ] Feature completely hidden on devices without Apple Intelligence
- [ ] First-time goal flow replaces blank stepper for new exercises
- [ ] Ongoing increase prompt fires after 5 consecutive goal-beating days
- [ ] "Not yet" snoozes for 14 days minimum
- [ ] Manual access from Settings → Goals → exercise
